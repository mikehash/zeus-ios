## Findings

### 1. Gate (b) must check the SPELLING, not just the existence

Wrote `client.provider().as_str()`. E0599.

`as_str` exists in that file — twice, at `zeus-core/src/lib.rs:917` and `:964` —
but on **other types**. `Provider` spells it `name()` (`:9054`). The habit was
formed by adjacent code, so it never registered as an assumption.

The form that catches it: find the `impl <Type>` opener, confirm the method sits
inside *that* impl with no column-0 `}` between them, and confirm the receiver
matches the call site. "The name exists in the crate" and "the name exists on
this type" are two readings; only the second is the gate.

### 2. Re-type the free function; do not inline it

The event type changed `String` → `AgentEvent`, which made the old `pump` dead
code — the compiler said so, unprompted. The tempting fix was to inline the
match into `send` and delete `pump` and its test.

That would have deleted the only guard. `send` needs a live provider, a network
and a key to reach; inlined, the token-ordering logic is unreachable from any
test. Re-typed to `Receiver<AgentEvent> -> Option<String>` instead, and added
the error leg as a second test. `None` means "`on_error` already delivered" —
`TokenSink` permits exactly one terminal call.

**Mutation-checked, file-scoped:** removing the early `return None` in
`src/lib.rs` fails `pump_reports_error_once_and_returns_none` and *nothing
else* — 15 passed, 1 failed. Restored: 16/16, 0 warnings, one target, so the
count has a scope.

### 3. An always-`None` FFI field is a wrong-subject signal

`SearchHit.line_number` had no producer that could ever fill it. To Swift that
does not read as "unimplemented" — it reads as "no match line found". Retired
rather than left dark.

### 4. Allow-list, never deny-list, when empty-allow is permissive

`is_tool_allowed` (`zeus-core:4666-4683`) treats an empty allow list as
"everything not denied". A deny-only phone build therefore *silently gains*
every tool a future registry adds.

Both lists are kept. Not redundant: the check is deny-first, so the denied names
are refused by two independent clauses, and the plausible future edit — "add a
tool" reads as a one-line change — still cannot widen past them.

`message` is denied for D1's reason: with `channels: None` it does not degrade,
it returns an explicit `Error::Tool` (`tools.rs:1002-1017`). A tool that can
only fail is worse than an absent one, because the model cannot see why.
